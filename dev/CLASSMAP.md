# Developer Class Map

> **Status**: Active  
> **Updated**: 2026-05-26  
> **Owner**: Core  
> **Purpose:** This document tracks callable entry points (services, commands, controllers, Twig components, Stimulus controllers). Keep it up to date as new classes are added or interfaces change. This document is meant to evolve alongside the codebase—treat it as a living index for developers to quickly discover callables without grepping through the project.  

## Map Structure

- Group entries by owning product or namespace boundary first, then by entry-point type.
- Keep sections stable even when they are temporarily small; this avoids one oversized service bucket as the project grows.
- Within a section, prefer namespace/lifecycle order over strict alphabetic order when that better reflects how contributors trace behavior.
- Add one row for callable services, controllers, commands, event payloads/subscribers, Twig extensions, frontend controllers, and templates that act as extension or override points.
- Use `Type` for semantic categories such as service, value object, enum, constants, interface, entity, repository, event payload, event subscriber, Twig extension, or operation action. Do not use Symfony service IDs unless an explicit custom service ID matters for discovery.
- Keep docs and test references as concrete paths. Use `N/A` only when no meaningful coverage or canonical document exists yet.
