# Account Link Reissue Slice

Status: implemented  
Created: 2026-05-28  
Owner: Codex

## Goal

Make account-link based onboarding and recovery more operationally complete by giving administrators a controlled reissue path and by preventing stale duplicate pending tokens from accumulating.

## Checklist

- [x] Add an admin action to reissue pending invitation, registration, and password-reset links.
- [x] Rotate the stored token hash and expiry when a link is reissued.
- [x] Use the existing account-link TTL for invitation and registration reissues and the fixed one-hour TTL for password-reset reissues.
- [x] Prevent admin invitations for email addresses that already belong to a user account.
- [x] Revoke older pending invitation/registration tokens when a new invitation or registration request is accepted.
- [x] Revoke older pending password-reset tokens when a new reset link is issued.
- [x] Keep self-registration enumeration-safe by returning the existing success state when the email already belongs to a user.
- [x] Emit a dedicated existing-account mail-flow key with the username when self-registration is requested for an existing user email.
- [x] Cover the reissue and duplicate-token behavior with targeted tests.
- [x] Update translations, class map, security draft, and worklog.
