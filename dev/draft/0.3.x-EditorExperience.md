# Editor experience (Feature Draft)

> **Status**: Draft  
> **Updated**: 2026-05-20   
> **Owner**: Core  
> **Purpose:** Draft for content editing, code editing, review flows, and safe administrative interactions.  

## Overview
- Defines editor functionality for content, templates, snippets, and structured fields.
- Covers draft states, validation feedback, diff previews, input preservation, and UI/UX expectations.
- Depends on error handling, schema-driven fields, and import/export collaboration.
- Keeps authoring workflows safe, reviewable, and friendly to human and LLM-assisted editing.

## Outline
The editor experience should prioritize safe changes over clever UI. Editors should be able to create, validate, preview, compare, save, publish, and recover content without losing work. Administrative screens should be functional and dense enough for repeated use, not marketing-style surfaces.

The editor should support structured field editing first, including language variants, generic variants, schema-specific inner rendering markup, and Markdown content fields. Richer template, snippet, and inline frontpage editing can build on the same validation, preview, diff, and permission foundations later.

Reference-heavy projects should remain friendly to edit. Editors should be able to select direct references, configure controlled query fields, preview resolved results, and later insert inline resolver tokens in Markdown without needing to understand the database structure behind the content graph.

Inline resolver tokens should be ergonomic in code editors. CodeMirror should be the preferred first editor for Markdown and schema/Twig editing, and should offer autocomplete for ref-links, query tokens, field targets, variants, and known entity titles where practical. CodeMirror is not a WYSIWYG rich-text editor; keep TinyMCE or another rich text/editor integration open as a later option.

LLM collaboration should influence editor design early. Imported operation sets, generated content proposals, and bulk modifications should always be reviewable through diffs before they change stored content.

Sanity is a useful broad reference for mature authoring and API-assisted collaboration, but Studio should not become headless-first. The web editor remains the preferred interaction path, and API/LLM workflows should reuse the same content validation, diff, revision, and publish services that power editor screens.

## Technical Specifications
- Use Symfony Forms for structured content editing where possible.
- Use Stimulus controllers for progressive enhancement.
- Use CodeMirror through the existing `code_editor_controller.js` and the native `@provider/editor/**` templates where code or markup editing is needed.
- Use CodeMirror for database-backed schema Twig editing when that feature is available.
- Use Markdown as the first rich text format.
- Provide editor controls for content reference fields and controlled query/list fields once those field types exist.
- Preview resolved references and query field results before publishing.
- Support inline resolver-token insertion in Markdown fields once the shortcode syntax is defined.
- Support autocomplete for inline ref-links and query tokens in CodeMirror where practical.
- Include suggestions for target entities, variants, field identifiers, and controlled query patterns once the resolver index exists.
- Keep TinyMCE or another editor integration open as a fallback if CodeMirror cannot support the required authoring workflow.
- Show validation errors for broken, ambiguous, forbidden, or ACL-restricted references.
- Keep template and snippet editing after content schema editing because schemas can already contain controlled Twig markup for inner fieldset rendering.
- Keep editor JavaScript small and feature-specific.
- Use translated labels, help text, validation messages, empty states, and buttons.
- Preserve input on validation failure.
- Provide preview before publishing when rendering is affected.
- Validate database-backed schema Twig before saving or activation and show actionable errors through the shared error-handling flow.
- Provide preview for schema Twig and variant-specific rendering before activation.
- Provide autosave or draft snapshots with configurable retention. Default retention should be 7 days.
- Provide editing UI for language variants and generic variants without treating them as the same concept.
- Use locale prefixes for language preview links when localized routing is enabled.
- Use query parameters or a reserved marker for generic variant preview links.
- Provide diff review for imports, generated changes, template edits, and destructive updates.
- Separate save, preview, publish, archive, and delete operations.
- Use voters or permissions for editor actions.
- Use CSRF protection for state-changing actions.
- Keep editor actions extensible through tagged services or documented hooks.
- Use AssetMapper/importmap entrypoints for editor-specific assets if needed.
- Keep inline frontpage editing deferred until structured editor flows are stable.
- Keep API-assisted and LLM-assisted editing aligned with the web editor by sharing domain services for validation, diff previews, revisions, and publish workflows.

## Testing & Validation
- Functional-test editor forms for valid saves and invalid submissions.
- Test input preservation after validation errors.
- Test permissions for each editor action.
- Test preview and publish boundaries separately.
- Test schema Twig validation, preview, and activation.
- Test language variant and generic variant editing flows separately.
- Test diff generation for operation sets before applying them.
- Test reference and query field editing once those field types exist.
- Test inline resolver-token insertion and validation once shortcode syntax exists.
- Test CodeMirror autocomplete for ref-links, query tokens, field identifiers, and variants once resolver-token syntax exists.
- Render editor routes with `.codex/render.php /<route>` when templates exist.
- Run translation comparison after editor copy changes.

## Implementation Notes
- **Decision recorded:** Build structured admin editing before inline frontpage editing.
- **Decision recorded:** Treat diff review as mandatory for imported or generated operation sets.
- **Decision recorded:** Keep editor actions extensible through tagged services.
- **Decision recorded:** The editor must treat language variants and generic variants as separate editing dimensions.
- **Decision recorded:** Database-backed schema Twig editing requires validation and preview before activation.
- **Decision recorded:** Markdown is the first supported rich text format.
- **Decision recorded:** Template and snippet editing ships after content schema editing.
- **Decision recorded:** Autosave or draft snapshots should use configurable retention with a 7-day default.
- **Decision recorded:** The editor should make direct references, controlled query fields, resolved previews, and future inline resolver tokens usable without exposing raw database mechanics.
- **Decision recorded:** Prefer CodeMirror autocomplete for ref-links, query tokens, field targets, variants, and entity-title suggestions where practical; keep TinyMCE or another editor integration open if CodeMirror is insufficient.
- **Decision recorded:** Use Sanity as a broad workflow reference without copying its model directly; Studio remains web-editor-first while exposing enough API structure for comfortable LLM collaboration.
