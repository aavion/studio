# Mailer Delivery Contract

> **Status**: Draft  
> **Updated**: 2026-05-28  
> **Owner**: Core  
> **Purpose:** Track the future mailer registry and delivery contract. Account flows are the first built-in registry entries.

## Direction

The mailer UI must learn available templates and replacement parameters from the mail context, not from whichever feature happens to send a mail. `App\Mail\MailFlowRegistry` is the current single source for mail flow metadata. It stores deterministic flow/template keys, grouping and label translation keys, and the allowed parameter keys for each template.

Later, core features and packages should register mail flows through a provider interface, including default Markdown templates and parameter metadata. Until that extension point exists, the registry is hard-coded with the account-management flows listed below.

## Built-In Account Flows

| Flow/template key | Purpose | Parameters |
|-------------------|---------|------------|
| `account.invitation.link` | User invitation setup link. | `email`, `action_url`, `expires_at` |
| `account.registration.link` | Auto-approved or admin-approved registration setup link. | `email`, `action_url`, `expires_at` |
| `account.password_reset.link` | Password-reset setup link. | `email`, `username`, `action_url`, `expires_at` |
| `account.registration.approval_requested` | Admin notification for a registration that requires approval. | `email` |
| `account.registration.approved` | User notification that a registration was approved. | `email` |
| `account.registration.rejected` | User notification that a registration was rejected. | `email` |
| `account.registration.existing_account` | Enumeration-safe notice for a registration attempt with an already registered address. | `email`, `username` |
| `account.password.changed` | User notice after a password change, including the security-review action link. | `email`, `username`, `action_url`, `expires_at` |
| `account.password_change.disputed` | Admin notification after a user clicks the password-change dispute link. | `email`, `username`, `user_uid` |
| `account.password_change.reactivated` | User notice after an admin reactivates a disputed account with a random password. | `email`, `username`, `user_uid` |

Locale resolution currently follows the delivery context: public flows prefer the user's stored language, then the current request locale; admin-triggered flows prefer the target user's stored language, then the configured default language.

## Notes

The real mailer will render localized Markdown templates to HTML and enqueue mail sending through Messenger. Until that service exists, `MessageLogAccountLinkDelivery` writes the exact payload shape the mailer boundary should receive into the message log. The action URL intentionally contains the current one-time token for local debugging; production delivery must replace or gate this stub before release.
