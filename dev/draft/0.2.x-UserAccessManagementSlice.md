# User and access management slice

> **Status**: Implementation checklist  
> **Updated**: 2026-05-28  
> **Owner**: Core  
> **Purpose:** Track the agreed feature-complete user-management slice before mail delivery ships.  

## Scope

This slice completes the functional user and access-management flows that can work before a real mailer exists. Mail-bound flows use a development delivery boundary that records outgoing links in the message log so tests and local UI checks can exercise the same token-based workflows. A later mailer slice should replace that delivery implementation for production use.

## Checklist

- [x] Add durable invitation/account-token support for invite, registration confirmation, and password reset flows.
- [x] Add a delivery boundary for account links and a message-log implementation for local/test use.
- [x] Implement Admin Users with list/detail, invitation creation, status changes, group assignment, and administrative password/reset-token actions.
- [x] Implement Admin ACL Groups with list/detail/create/edit, locked preset protection, access-level validation, and safe deletion guardrails.
- [x] Implement user profile editing and keep password-change auditing intact.
- [x] Implement API-key generation, revocation, and password re-authenticated key reveal using the existing reversible encrypted storage.
- [x] Implement registration modes: disabled, admin approval, and auto approval. Registration creates the same token acceptance flow as invitations with the `registered` ACL group preselected.
- [x] Implement invitation acceptance where the invited user chooses username and password.
- [x] Implement password reset request and token completion using the same account-link delivery boundary.
- [x] Keep user-facing strings translated in all language source catalogues.
- [x] Update tests, class map, docs, and worklog with the implemented behavior and remaining mailer follow-up.
- [x] If migrations change, remove the local development SQLite database so UI checks can reinitialize it cleanly.

## Deferred Follow-Ups

- Decide whether the development delivery implementation remains available behind a debug-only configuration gate.
