# Account Mail Delivery Contract Slice

> **Status**: Draft  
> **Updated**: 2026-05-28  
> **Owner**: Core  
> **Purpose:** Track the pre-mailer account-flow delivery contract before the real mailer and template editor are implemented.

## Checklist

- [x] Register every account mail flow in one deterministic registry with template keys, grouping metadata, and supported replacement parameters.
- [x] Route the intended mail locale through public, user, and admin-triggered account flows.
- [x] Keep replacement parameter names short and stable, such as `email`, `username`, `action_url`, `expires_at`, and `user_uid`.
- [x] Replace the account-link message-log implementation with a mailer-shaped DEBUG stub payload.
- [x] Keep clear action URLs in the stub while no real mailer exists so local account flows remain testable.
- [x] Cover registry completeness, locale resolution, and message-log payload shape with focused tests.
- [x] Update the worklog, class map, and logging/manual notes.

## Notes

The real mailer will render localized Markdown templates to HTML and enqueue mail sending through Messenger. Until that service exists, `MessageLogAccountLinkDelivery` writes the exact payload shape the mailer boundary should receive into the message log. The action URL intentionally contains the current one-time token for local debugging; production delivery must replace or gate this stub before release.
